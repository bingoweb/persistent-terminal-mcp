# Persistent Terminal MCP v0.10.0

`v0.10.0` is the high-trust administration and performance release following the first stable pre-1.0 `v0.9.0` line.

## Highlights

- administrative mutations use capability-first `privilege:auto` by default and escalate only after a concrete privilege denial;
- operators can opt into `PTEXT_ROOT_TARGETS=*` when every configured OpenSSH target is intentionally administrable;
- signal `0` is supported for non-delivering process existence/permission probes;
- ordinary SSH execution avoids the redundant `ssh -G` preflight process;
- structured remote filesystem operations reuse a content-addressed helper cached on each target;
- lifecycle state avoids repeated JSON disk reads inside the long-running extension process.

Correctness controls remain in place: host-key verification is not disabled, secret bytes stay outside ordinary tool arguments/logs/state, ambiguous side-effect calls are not replayed, managed process/session identities are verified before destructive cleanup, and filesystem writes retain atomic/checksum protections.

## Verification

The release gate includes source checks, the deterministic test suite, third-party license validation, release metadata verification, production dependency audit, clean-install artifact smoke, and the existing live acceptance harness. The changed paths additionally received a live `taylan` source-path test and post-deployment MCP `tools/list` / signal-0 privilege test.

## Release artifacts

The release tooling produces:

- `persistent-terminal-mcp-0.10.0.tgz` — restricted runtime package;
- `persistent-terminal-mcp-0.10.0-source.tar.gz` — standalone source archive;
- `persistent-terminal-mcp-0.10.0.cdx.json` — CycloneDX SBOM;
- `SHA256SUMS` — SHA-256 integrity manifest.

## Rollback

Production deployment retains a known-good previous runtime and the previous LaunchAgent policy. If a post-deployment health check regresses, restore that runtime/policy and restart only the extension failure domain; upstream `pty-mcp` and remote `ai-tmux` sessions do not need to be destroyed.
