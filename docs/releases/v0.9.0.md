# Persistent Terminal MCP v0.9.0

`v0.9.0` is the first stable pre-1.0 release of Persistent Terminal MCP. It is the release cut from the implementation that completed the eight planned capability slices and the full live failure-injection acceptance suite.

## Highlights

- Persistent SSH terminal sessions survive client and local extension reconnects through upstream `pty-mcp` plus remote `ai-tmux`.
- Structured `remote_exec`, remote filesystem, deterministic patch/search, transfer/resume/sync, SHA-256 integrity, port forwarding, and persistent task management are available through one MCP surface.
- `remote_root_exec` uses explicit, auditable best-effort root acquisition and keeps password material out of ordinary MCP arguments, logs, persisted state, and model-visible output.
- System/process/service/journal/disk/GPU helpers use normalized structured results; ordinary commands remain non-root unless privilege is explicitly requested.
- Reconnect is single-flight with bounded backoff. Ambiguous tool-call transport loss is not replayed; a definitive stale upstream MCP session (`-32001 Session not found`) is the one safe retry case.
- Production reconnect events now flow through the redaction-first rotating JSONL logger rather than leaving the logger as an unused library component.

## Compatibility

This is a stable **major-zero** release. The implementation and deployment are intended for production use, but the public MCP tool surface has not been frozen as a `1.0.0` API contract. A future minor `0.x.0` may still reshape that surface when there is a strong reason to do so.

New integrations should use canonical names. `ssh_exec`, `ssh_ensure_session`, and `ssh_read_session` are retained only as deprecated compatibility aliases.

## Release assets

The GitHub Release publishes:

- `persistent-terminal-mcp-0.9.0.tgz` — runtime package, excluding tests and repository-development files;
- `persistent-terminal-mcp-0.9.0-source.tar.gz` — source archive of the exact standalone release tree;
- `persistent-terminal-mcp-0.9.0.cdx.json` — CycloneDX application SBOM;
- `SHA256SUMS` — SHA-256 hashes for the runtime package, source archive, and SBOM.

The runtime tarball is extracted into a clean temporary directory, production dependencies are installed from scratch, and an MCP initialize/tools-list smoke is required before the release is allowed to publish.

## Verification

The release gate includes the full deterministic suite, source checks, third-party license inventory, production `npm audit`, clean-install artifact smoke, deployment contract checks, and the existing 15-phase live acceptance harness. Public GitHub tagging happens only after the exact `0.9.0` tree has passed those local and live gates.

## Rollback

Production deployment retains one known-good previous runtime outside the mutable source checkout. If a post-deployment health check regresses, rollback swaps that retained runtime back into the stable application path and restarts only the extension failure domain. It does not kill upstream `pty-mcp`, remote `ai-tmux` sessions, or rewrite Git history. A failed release tag is never force-moved; a correction is published as a new version.
