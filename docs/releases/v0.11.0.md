# Persistent Terminal MCP v0.11.0

`v0.11.0` is the High-Trust Power Core release. It keeps the existing public MCP/OAuth identity and upstream `pty-mcp` failure domain while adding connection reuse, target capability/diagnostic intelligence, proof-preserving privilege selection, generic systemd administration, verified transactional rollback, protocol annotations, and bounded runtime health telemetry.

The 0.11.0 source tree completed deterministic, source-path, deployed restart-survival, independent MCP conformance, Inspector, and bounded burn-in gates before publication. Production now runs 0.11.0 behind the guarded localhost transport; public tag/public-repository publication remains a separate immutable release step rather than being inferred from deployment.

## Transport and target intelligence

- native OpenSSH **ControlMaster** reuse is managed through a private hashed ControlPath with bounded target count, single-flight initial connection, native `ssh -O check` verification, owned `ssh -O exit` cleanup, and stale-master recovery;
- `PTEXT_SSH_MULTIPLEX=auto` preserves one-shot fallback when a reusable master cannot be established, while `required` fails before dispatch rather than silently changing semantics;
- short ControlPath selection avoids the real Unix-domain path-length failure discovered during live macOS/OpenSSH acceptance;
- `target_capabilities` caches positive and negative capability evidence with a bounded TTL, invalidates on resolved SSH-identity change, and never caches transport/probe failures;
- `target_diagnose` synthesizes transport/multiplex, remote identity, OS/kernel/uptime, capabilities, privilege state, `ai-tmux`, disk pressure, failed-systemd count, optional GPU state, capability-cache state and fixed-vocabulary telemetry without returning raw diagnostic payloads.

## Privilege Engine 2.0 and systemd administration

- **Privilege Engine 2.0** remembers only a non-secret preference among proven automatic providers (`direct_root`, `sudo_nopasswd`, `docker_host_root`);
- cached preference changes provider ordering only: every privileged execution still performs the provider's live UID-0/capability proof before dispatch;
- password-backed sudo/su providers are never cached as automatic preference and retain the existing secret-safe prompt path;
- generic systemd inspection covers service, socket, timer, path, mount, automount, target, slice and scope units;
- `systemd_unit_action` exposes a closed action vocabulary and escalates in `auto` mode only after a real privilege denial rather than an ordinary application/unit failure;
- canonical systemd `\xHH` escaped unit names are accepted while arbitrary backslashes and shell syntax remain rejected;
- existing service-oriented compatibility tools continue through the same generic core where their semantics match.

## Verified transactional administration

`admin_transaction` performs exactly one enumerated reversible mutation (`systemd_action`, `remote_write`, or `remote_patch`) behind optional precheck and bounded health gates.

- UTF-8 rollback material is kept only in process memory and capped at 1 MiB;
- file rollback uses optimistic SHA-256 conflict detection and then re-reads the restored file to verify the final SHA-256;
- deterministic systemd pre-state mappings are restored and re-verified after rollback;
- a mutation lost behind ambiguous transport failure is never guessed or replayed;
- rollback conflicts/failures remain visible as `rollback_failed` instead of being hidden by the original health error.

## MCP protocol quality

All 49 canonical extension-owned tools and the three deprecated extension aliases publish the four advisory MCP tool annotations:

- `readOnlyHint`
- `destructiveHint`
- `idempotentHint`
- `openWorldHint`

The policy is explicit and conservative; restart/transaction-class operations are not claimed idempotent. Upstream `pty-mcp` tool objects and upstream annotations are not rewritten. These hints are descriptive protocol metadata only and do not replace validation, target allowlists, privilege checks, secret handling or host-key policy.

## Runtime health and telemetry

`terminal_health` retains extension/upstream/gateway health, lifecycle counts, target `ai-tmux` compatibility, reconnect counters and failure totals, and now adds a closed payload-free `runtime` summary:

- fixed-vocabulary timing/counter telemetry;
- multiplex mode and active master count;
- capability-cache entry/pending counts and TTL;
- non-secret Privilege Engine provider-cache counts.

Command text, file contents/paths, ControlPath values, target-hash lists, credentials and terminal scrollback are not runtime telemetry fields. A broken snapshot source is isolated as unavailable evidence rather than making health itself fail.

## Compatibility and public topology

- public endpoint remains `https://pty.taylansoylu.com/mcp`;
- OAuth scope remains `pty`;
- localhost transport is guarded as `:9031 guard -> :9032 extension -> :9021 upstream pty-mcp`, while the existing OAuth gateway remains on `:9022` and continues to target `:9031`;
- the localhost guard rejects non-local Host/Origin values before they can reach `mcp-proxy`, while preserving byte-stream HTTP/SSE behavior for valid localhost clients;
- upstream `pty-mcp` remains an independent failure domain and its tools/results remain passthrough;
- remote persistent PTYs remain owned by `ai-tmux`, so an extension deployment/restart does not require destroying remote shells;
- deprecated `ssh_exec`, `ssh_ensure_session`, and `ssh_read_session` aliases remain available for compatibility.

## Release artifacts

The release tooling produces:

- `persistent-terminal-mcp-0.11.0.tgz` — restricted runtime package;
- `persistent-terminal-mcp-0.11.0-source.tar.gz` — standalone source archive;
- `persistent-terminal-mcp-0.11.0.cdx.json` — CycloneDX SBOM;
- `SHA256SUMS` — SHA-256 integrity manifest.

The runtime package excludes development-only test/workflow trees. The source archive uses the standalone repository root layout, and artifact generation performs a clean-install smoke before release publication.

Release tooling also verifies the **source archive's own committed release identity**: the archived `package.json` version, changelog entry, and `docs/releases/v0.11.0.md` must match the requested artifact version. This prevents a dirty working-tree runtime package from being combined with a stale `git archive HEAD` source tarball under the same 0.11.0 artifact name.

## Rollback

Production deployment retains the previous known-good runtime in the dedicated rollback slot. Deployment stages a new runtime first, restarts/probes only the extension failure domain, and restores the retained runtime if the functional extension probe fails. Upstream `pty-mcp`, the OAuth gateway identity, and remote `ai-tmux` sessions are not destroyed as part of an extension rollback.
